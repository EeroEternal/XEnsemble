# XEnsemble 核心交互设计规范 (Workspace-Centric UX)

> **版本**：v1.0  
> **定位**：面向小白友好的 AI Agent 编程工作台交互模型与界面规范。  
> **核心模型**：`Workspace` 是中心，`Agent Session` 围绕 Workspace 协同，`Git / PR` 贯穿整个开发生命周期。

---

## 1. 核心设计原则与概念模型

### 1.1 概念降维：只保留一个一级概念「Workspace」

为避免给初学者/小白用户带来认知负担，**对用户完全隐藏“项目（Project）”这一中间层级**，仅暴露统一概念：**Workspace（工作空间）**。

* **Workspace 是什么**：包含代码库、运行与依赖环境（Runtime/Sandbox）、Git 分支状态、部署/预览以及挂载在其上的所有 Agent Session 的独立开发单元。
* **概念对应关系**：
  * ❌ 错误层级：`选择项目 -> 创建 Workspace -> 选择 Agent`（概念重叠，小白无法区分）
  * ✅ 正确层级：`代码来源 (GitHub/本地/模版) -> 自动构建 Workspace -> 启动/切换 Agent Sessions`

```
┌─────────────────────────────────────────────────────────────┐
│                          Workspace                          │
│                                                             │
│  ┌───────────────────┐  ┌────────────────────────────────┐  │
│  │    代码与环境      │  │         Git / PR 状态          │  │
│  │ (FS + Sandbox/PTY)│  │ (Branch, Diffs, Sync, PR)    │  │
│  └───────────────────┘  └────────────────────────────────┘  │
│                                                             │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                    Agent Sessions                     │  │
│  │  ┌─────────────────┐ ┌───────────────┐ ┌───────────┐  │  │
│  │  │ Claude Session  │ │ Kimi Session  │ │ Codex...  │  │  │
│  │  └─────────────────┘ └───────────────┘ └───────────┘  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 2. 新用户上手与创建路径 (Onboarding Flow)

小白用户的首次旅程必须做到**“零阻断、意图驱动、渐进式引导”**。

```mermaid
flowchart TD
    A[点击新建 Workspace] --> B{选择代码来源}
    B -->|从 GitHub 导入| C[输入/选择 Repo URL]
    B -->|导入本地目录| D[选择本地文件夹]
    B -->|空白项目| E[选择模版 React/Node/Python...]
    
    C --> F[系统自动化准备环境]
    D --> F
    E --> F
    
    F --> G{是否有 Git 仓库?}
    G -->|已配置| H[展示当前分支与远程状态]
    G -->|无 Git 目录| I[进入工作台, 顶部显示一键启用 Git 提示]
    
    H --> J[选择首个 Agent (Claude / Kimi / 推荐)]
    I --> J
    J --> K[进入 Workspace 主开发界面]
```

### 2.1 来源选择与防呆机制
1. **GitHub 导入**：自动绑定远程 upstream 与当前活跃分支。
2. **本地目录导入**：
   - 若本地目录没有 `.git`，**绝对不弹错阻断**，正常拉起 Workspace。
   - 在 Workspace 顶栏或 Git 面板以轻量标签提示：`[📦 启用 Git 版本控制 / 关联 GitHub]`。
3. **环境初始化反馈**：
   - 展现友好的 Checklist 动效（`正在准备环境...` -> `拉取依赖...` -> `环境就绪`），不把原始复杂的底层报错直接甩给用户。

## 3. 工作台核心界面布局 (Workspace Layout)

界面必须在“**保证 Agent 对话/代码编辑大视野**”与“**Git 变更的醒目可见度**”之间取得平衡。

```
+----------------------------------------------------------------------------------------------------+
|  [Logo]  Workspace: my-app  |  [🌿 main | 3 files changed | ⬆ 1]  [🔄 Sync] [🚀 Create PR]  | 用户 |
+----------------------+----------------------------------------------+------------------------------+
| 📁 Workspace 资源     | 💬 Agent Session (当前：Claude 3.7)          | 🔀 Git 交付 & 审核面板       |
|                      |                                              | (可折叠/有改动时自动唤醒)    |
| - Sessions           | [Agent 消息流 & 工具执行状态]                 +------------------------------+
|   ├ 🔵 Claude (当前)  |                                              | 📝 变动摘要 (AI 自动归纳)     |
|   ├ ⚪ Kimi (长文重构)|                                              | • src/api.ts (+24, -5)       |
|   └ ➕ 新建 Session   |                                              | • package.json (+2)          |
|                      |----------------------------------------------+------------------------------+
| - 文件树 / Explorer  | 💻 代码编辑 / Diff 检视 / Preview 运行效果    | ⚡ 一键交付操作              |
|   ├ src/             |                                              | [ 提交并同步 (Commit & Push) ]|
|   └ ...              |                                              | [ 撤销本次修改 (Discard) ]   |
+----------------------+----------------------------------------------+------------------------------+
```

### 3.1 顶栏（Status Bar）：Git 与环境的持久心跳
* **常驻信息**：
  * 当前 Git 分支（如 `🌿 main` 或 `🌿 feature/login`）。
  * 状态指示标签：`3 files changed`、`⬆ 1 待推送`、`与远程保持一致`。
* **高频直达按钮**：
  * `[🔄 Sync / 同步]`：自动 Pull & Push。
  * `[🚀 Create PR / 发起合并]`：直接唤起 PR 提审对话框。

### 3.2 左侧栏（Navigator）：Workspace 与多 Session 管理
* **Session 切换区（置顶）**：
  * 列出当前 Workspace 下的所有 Agent 会话（如 `Claude 架构优化`、`Codex 单元测试`）。
  * **切换交互**：点击直接切换会话，保留各 Agent 的上下文、命令历史与终端状态。
  * **新建按钮**：`[+ New Session]`，弹窗快速选择 Agent 种类与预设角色。
* **文件资源树**：展示工作空间内的项目文件与目录。

### 3.3 中间主画布（Workspace Canvas）：双模态工作区
* **上半区 / 主区：Agent 交互流水线**
  * 用户 Prompt 输入与多模态交互。
  * Agent 执行日志（调用 Bash、文件读写、MCP 工具的折叠展示）。
* **下半区 / 标签页：成果呈现区**
  * 选项卡支持：`Diff 检视`、`终端 Terminal`、`Web Preview (预览)`。

## 4. Git / PR 交互工作流规范（面向小白的任务化设计）

避免直接展示复杂的 Git 命令行指令或冷冰冰的 Git Graph，将 Git 操作包装为 **“AI 交付审核流”**。

### 4.1 智能唤醒逻辑
* **平静期（无修改）**：右侧 Git 面板可收起或作为窄工具条，最大化代码与 Agent 对话视野。
* **产出期（Agent 修改了代码）**：
  * 顶栏变更数字更新，Git 面板出现轻量提示。
  * AI 自动生成一句话变更总结（如：*“已修复鉴权过期重试机制，涉及 2 个文件”*）。

### 4.2 小白友好的操作文案对照

| 传统专业 Git 术语 | XEnsemble 小白友好文案 | 交互行为 |
| :--- | :--- | :--- |
| `git status / diff` | **查看本次修改 (Changes)** | 点击直接在主画布开启左右 Diff 比较 |
| `git add & git commit` | **保存并记录改动 (Save Changes)** | 自动以 AI 生成的 Commit message 暂存提交 |
| `git push & pull` | **同步到云端 (Sync)** | 一键拉取并推送最新代码 |
| `gh pr create` | **发起代码合并 (Create PR)** | 自动填充标题与描述，一键推送到 GitHub PR |
| `git restore / reset` | **撤销修改 (Discard)** | 弹窗二次确认后还原文件 |
| `merge conflict` | **解决冲突 (Resolve Conflict)** | 标注冲突位置，提供 `[让 AI 帮我解决冲突]` 辅助按钮 |

## 5. Agent 切换与 Session 隔离机制

### 5.1 明确“切换”模型
* **原则**：**切换 Agent = 切换/新建 Session**。
* **理由**：
  1. 不同模型（Claude 3.7 / Kimi / Qwen / GPT）的系统提示词（System Prompt）、Token 计费、上下文窗口和工具调用协议各异。
  2. 避免用户产生“在同一个流里无损热替换大脑”的误解，防止终端执行状态和上下文错乱。
* **多 Agent 协同场景**：
  * **Session A (Claude)**：负责大模块架构重构，生成代码并提交至 Workspace。
  * **Session B (Kimi/Codex)**：用户切换到 Session B，输入 *“请审查刚才 Session A 修改的代码并补充单测”*，Session B 直接读取 Workspace 的最新文件系统开展工作。

## 6. 界面组件与样式实现对齐 (Design Tokens)

严格对齐项目已有 UI 规范（`DESIGN.md` 与 `docs/Designs.md`）：

1. **下拉选择器**：
   - 严禁使用原生 `<select>`。
   - Agent 选择器与分支选择器必须使用 `web/src/components/SelectMenu.jsx`。
2. **按钮与焦点**：
   - 所有按钮禁止外边框高亮（focus ring），统一应用 `consoleButtonFocusClass` / `buttonStyles.js`。
   - 图标按钮（如 Sync、收起面板、刷新）统一使用 `consoleIconButtonClass`，不可带文字并排。
3. **弹窗与聚焦**：
   - 新建 Workspace / 创建 PR 弹窗打开后，主输入框必须自动聚焦（`autoFocus`）。
4. **异步操作反馈**：
   - 点击 `Sync` 或 `Create PR` 时，按钮立即置灰 (`disabled`)，图标替换为旋转的 `Loader2`。
   - 结果通知必须使用 `useToast('success' | 'error')`，严禁在页面内堆砌红绿文字 banner。
